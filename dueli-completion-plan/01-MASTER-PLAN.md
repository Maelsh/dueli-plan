# Dueli — الخطة الشاملة لإكمال الويب

**الإصدار: 2026-10-01.** هذه النسخة تجمع الخطة الأصلية وملحق سبتمبر 30 ومراجعات GLM/Kimi/Arena/Opus/Sonnet. هي مرجع تكليف التنفيذ؛ لا تعني اعتماد قرارات المنتج المفتوحة أو إعلان اكتمال التنفيذ.

المستودع: https://github.com/Maelsh/dueli-opus
الخطة: https://github.com/Maelsh/dueli-plan/tree/main/dueli-completion-plan
مرجع الكود عند الصياغة: `409dd8a833de0977db945265a1e55c3adc33c122` (بعد دمج #74).
**حالة المالك: R1 مكتملة؛ B7 متوقفة؛ R0/R2/R3/R4 لم تبدأ؛ R5 بعد إطلاق الويب.** B7 اسم بند إصلاح التمرير الحالي، وليس إعادة فتح بوابة Beta Core التاريخية.

## 1. قواعد النطاق

1. خطة 16 وBackend وTURN والخوادم والبث والمال والإعلانات المغلقة لا تعاد. R1 مغلقة ولا تفحص مجدداً. لا جرد شامل ولا full suite متكرر ولا اختبار أنظمة قديمة لمجرد الانتقال.
2. المتبقي هنا: رحلة المنتج الناقصة، عيوب جديدة محددة من تقارير الاستخدام، اكتشاف وبحث ومطابقة، بنك وإدارة ومساعدة ووثائق وقبول. يجوز تعديل العقد/الخلفية الضرورية للعيب المحدد؛ لا إخفاء خلل منطقي في الواجهة ولا إعادة بناء الخدمة.
3. قرار المالك **التقييم أثناء البث فقط ويغلق بانتهائه**. التسجيل للعرض والقراءة؛ لا تقييم جديد بعد النهاية. الأثر الضروري على الحسم/ELO/توقيت التوزيع ضمن R2-V.
4. تثبت نسب 20% للمنصة و80% للحوض، توزيع الحوض حسب مجموع تقييمات الطرفين، والفائز حسب المتوسطات وقواعد التعادل القائمة، والدقة بالسنتات وحراسات ELO/التوزيع لمرة واحدة. لا إعادة احتساب تاريخي.
5. KEEP NOW للتخليقي ثابتة؛ لا حذف تلقائي أو migration تقاعد. لا استنتاج دين/مذهب من التصفح للتخصيص.
6. LOCAL تنفيذ → REMOTE مستقل → القائد يدمج → يحدّث 04 → يعطي الوحدة التالية. لا PR شكلي لما هو منجز؛ ALREADY DONE بدليل موضعي كافٍ. لا دمج كود بلا مراجعة مستقلة.
7. OOP/MVC، SQL في Models، خدمات مركزية، ar/en وRTL/LTR، CSP والعقود الحالية. لا إعادة بناء إطار العمل أو خدمات مدفوعة جديدة.
8. 01 يحدد النطاق؛ 02 عمل القائد؛ 03 الوحدات والموجهات؛ 04 الحالة؛ 05 المواصفة التقنية؛ 07 خلاصة حسم المراجعات. 06 موجه مراجعة تاريخي انتهت مهمته، لا يرسل مجدداً.

## 3. ترتيب التكليف الافتراضي

**B7 → J → L1 → V → L2 → A → M → P → F → D1 → D2 → C1 → C2 → C3 → R4.**

R0 تبدأ بالتوازي مع B7، وD0 يعتمد من 05 قبل D1؛ لا تنتظر البنك لعمل غير مالي. يمكن تقديم A/M/P/C1/C2 أو تشغيلها بالتوازي إذا توفر منفذون ووزع القائد الملفات بلا تعارض. D1 لا ينتظر جلسة S، لكنه يعتمد على قرارات الترتيب وبيانات مشاهدة مصححة إن استخدمها. L2 لا تبدأ جلسة S قبل جاهزية V. 03 يسجل الاعتماديات ومعايير الإغلاق.

## 4. النطاق الأصلي محفوظ

- الأنواع الخمسة: مشاهد→منافسة، منافسات مشابهة، مستخدمون للمتابعة/المواجهة، منافسة→منافس، منافس→منافسات. البحث مسار قصد مستقل.
- البنك الخارجي للمنصة والإجراءات الواقعية في R0 يختلف عن واجهة طريقة صرف مستخدم في R2-P.
- المساعدة: tooltips مترجمة ومتاحة، FAQ، أدلة إنشاء/مشاركة/مشاهدة وتبرع وسحب، وحالات فراغ/تحميل/خطأ واضحة.
- الوثائق بحسب الحاجة الفعلية: الخصوصية والشروط والكوكيز والمجتمع والمحتوى والملكية والبلاغات والحذف والدفع/الاسترداد/التبرع/السحب والمنافسة والتقييم. لا إلزام بوثيقة مستقلة لكل عنوان.
- العربية/الإنجليزية، الأرقام والتواريخ والعملات، RTL/LTR، focus والتكبير وقارئ الشاشة، الجوال والشاشة الكبيرة. اختبارات موضوعية آلية أولاً؛ الأداء يعالج عند قياس عائق محدد، لا بوابة عامة.
- لا تُسقط القدرة المطلوبة إلى backlog إلا بقرار مالك واضح مع أثره على الإطلاق. «منجز خلفياً» لا يساوي «رحلة واجهة مكتملة».

## 5. القبول وحدود الكلفة

**T:** الحسابات والحالات والصلاحيات والأهلية والسباقات والحفظ والأعداد والخوارزميات والpagination؛ محلي ثم مراجع مستقل.
**B:** رحلة متصفح وDOM/شبكة/console وPlaywright؛ لا Astra افتراضياً.
**S:** رؤية/سماع الوسائط الفعلية، لمس/جهاز أو قارئ شاشة مسموع وحكم تجربة لا تجيب عنه T/B. تجمع قرب R4؛ BLOCKED DEVICE إذا غابت القدرة، وليس فشل خادم أو PASS.
**H:** تفويض مسؤول وبنك وكيان ووثائق وقرار إطلاق. لا نموذج يستبدل صاحب الصلاحية.

رحلات R4: زائر→اكتشاف/بحث/مشاهدة→حساب؛ حساب/استعادة/OAuth/إعدادات/حذف؛ مشاهد متابعة/رسالة/إشعار/تعليق/تقييم حي/تبرع؛ منشئ دعوة→قبول→بث→نتيجة؛ منافس اكتشاف مشاركة→أرباح→طريقة صرف→سحب؛ مسؤول إشراف/تحكيم/رد دعم؛ معلن حملة/عرض/تقرير. يعاد استخدام قبول T/B للوحدات ولا يكرر شاملاً.

إثبات بث A/B يصل إلى C ثم التسجيل **قبول الربط الإنتاجي الجديد**، لا إعادة بوابة TURN/خوادم/بث مغلقة. الحسابات الاختبارية الثلاثة الحالية كافية؛ أسرارها خارج GitHub والتقارير؛ لا مراسلات للناس ولا أموال أو حذف بيانات حقيقية للاختبار.

## 6. تعريف إكمال الويب

كل وحدة مطلوبة لها DONE أو ALREADY DONE أو تأجيل معتمد لا يحجب الإطلاق، مع PR/SHA ودليل قبول مستهدف. رحلة المنافسة كاملة من الدعوة إلى مشاهدة التسجيل، تقييم حي مغلق بالنهاية ونتيجة ثابتة، اكتشاف حتى النفاد، رسائل وبنك وإدارة وإعلان قابلة للاستخدام. R0 اللازمة منجزة وR4 مقبولة والمالك يتخذ قرار الإطلاق. دمج هذه الوثيقة وحده لا يكمل المشروع.
